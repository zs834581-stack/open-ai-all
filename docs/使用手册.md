# proxy-desktop 操作手册

本地 AI 网关使用手册：把各家网页版模型（DeepSeek / Kimi / 通义千问 / 智谱 GLM / MiniMax 等）转成标准 OpenAI API，聚合后接入任意 AI Agent。

---

## 0. 前置条件与产物清单

### 0.1 从哪来

GitHub 私有仓库 **Actions → Build Windows Release** 运行成功后，在页面底部 `Artifacts` 下载 `proxy-desktop-windows`，解压得到以下目录：

```
proxy-desktop-windows/
├─ new-api.exe          网关 + Web 控制台（约 138 MB）
├─ launcher.exe         启动器（约 37 MB）
├─ config.json          配置（可直接用记事本改）
├─ data/                new-api 运行数据（数据库 / 日志），启动时会自动重建
├─ chat2api/            转换层（Electron 桌面应用）
│  └─ Chat2API.exe
└─ free-api/            可选：Node 版独立转换服务（默认关闭）
```

### 0.2 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11 x64 |
| 端口 | 3000（网关）、8080（转换层）未被占用 |
| 运行库 | 无需安装 Node / Go / Python，全部为绿色版 |
| 网络 | 能访问各 AI 平台网页版（Chat2API 走网页协议） |

### 0.3 整体链路

```
各厂家网页版账号（Cookie / Token）
        │
        ▼
Chat2API  :8080   ← 转成 OpenAI 兼容 API（/v1/chat/completions）
        │
        ▼
new-api   :3000   ← 聚合 / 多渠道路由 / 额度 / 生成 sk- 令牌
        │
        ▼
AI Agent（opencode / WorkBuddy / Cursor / Cline / Dify / 任意 SDK）
```

## 1. 启动

打开 PowerShell，进入解压目录：

```powershell
cd C:\Users\<你>\Downloads\proxy-desktop-windows
.\launcher.exe start
```

启动器会依次：

1. 自动创建 `data\` 目录（已存在则跳过）；
2. 拉起 `new-api.exe`，监听 **3000**；
3. 拉起 `chat2api\Chat2API.exe`（桌面窗口会弹出）；
4. 约 2.5 秒后自动打开浏览器 `http://localhost:3000`。

正常日志形如：

```
[launcher] 启动中…
[new-api] ...
[chat2api] ...
[launcher] 打开 Web 控制台: http://localhost:3000/
```

> 建议用终端启动而非双击，这样能看到日志。关闭窗口或按 `Ctrl+C` 会一并结束子进程。

### 1.1 首次登录 new-api

浏览器打开 `http://localhost:3000`

| 项 | 值 |
|---|---|
| 用户名 | `root` |
| 初始密码 | **`123456`** |

> ⚠️ 登录后**立即**到 `设置` / 用户菜单修改密码。该密码是 new-api 源码写死的默认值，公网可达时会成为明显风险（本机自用风险较低）。

## 2. Chat2API：把网页账号变成 API（:8080）

### 2.1 添加平台账号

在 Chat2API 窗口左侧进入 `Providers`（供应商），逐个添加：

| 平台 | 凭证获取方式 |
|---|---|
| DeepSeek | 登录 `chat.deepseek.com` → F12 → Application → Local Storage，复制 `userToken` 的值 |
| Kimi | 登录 `kimi.com` → F12，复制登录态 JWT |
| 通义千问 Qwen | 登录通义千问网页 → 复制 `tongyi_sso_ticket` |
| 智谱 GLM | 登录 `chatglm.cn` / `bigmodel.cn` → 复制 `refresh_token` |
| Z.ai / MiniMax / Mimo / Perplexity | 同上，取各自登录态 token |

> 部分平台支持在 `Providers` 里直接点「登录」按钮，用内置浏览器扫码/账号登录后自动抓取凭证，比手工复制省事。

同一平台可添加**多个账号**，Chat2API 会做负载均衡（轮询 / 填充 / 故障转移）。

### 2.2 启动代理

进入 `Proxy`（代理）页面：

1. 确认端口为 **8080**（如需修改，改这里和 `config.json` 里的 `chat2api.port` 保持一致）；
2. 点击 `Start Proxy`；
3. 状态变为运行中即可。

验证：浏览器访问 <http://127.0.0.1:8080/v1/models>，应返回 JSON 模型列表。

### 2.3 开启 API 鉴权（建议）

进入 `API Keys`（API 密钥）页面：

1. 打开「启用认证」开关；
2. 生成一个密钥并复制保存。

> 默认 **不启用认证**（源码 `enableApiKey: false`），此时任何 key 都能通过。仅本机使用可不开；若同机有其他程序、或以后要做端口映射，务必开启。

## 3. new-api：建渠道 + 建令牌（:3000）

登录 `http://localhost:3000` 后，做两件事：**把 Chat2API 接成渠道**，**生成给 Agent 用的密钥**。

### 3.1 新建渠道

左侧 `渠道` → `新建`，按下表填写：

| 字段 | 填写内容 | 说明 |
|---|---|---|
| 类型 | **OpenAI** | 类型 1，会自动拼接 `/v1/chat/completions` |
| 名称 | `chat2api` | 任意 |
| 代理地址 / Base URL | `http://127.0.0.1:8080` | **结尾不要带 `/v1`** |
| 密钥 | Chat2API 里生成的 key | 若未开鉴权，随便填一个非空值 |
| 模型 | 点「获取模型列表」自动拉取；或手填，一行一个 | 见附录 A |
| 分组 | `default` | 与令牌的分组保持一致 |

保存后，点该渠道行的「测试」按钮，返回成功即链路打通。

> **重要**：若类型选「自定义渠道」（type 8），new-api 会**原样使用** Base URL、不追加任何路径，此时必须写全 `http://127.0.0.1:8080/v1/chat/completions`。选 OpenAI 类型更省事，按上表填即可。

### 3.2 生成令牌（Agent 用的 API Key）

左侧 `令牌` → `添加令牌`：

| 字段 | 建议值 |
|---|---|
| 名称 | `agent` |
| 额度 | 留空 = 无限 |
| 过期时间 | 留空 = 永不过期 |
| 分组 | `default`（必须与渠道分组一致） |

保存后回到列表，复制以 `sk-` 开头的密钥（后端为 48 位随机串）。

### 3.3 两层密钥不要混用

| 密钥 | 用在哪 | 形态 |
|---|---|---|
| Chat2API 的 key | 只填在 new-api 的**渠道**里 | 自定义串 |
| new-api 的令牌 | 给 **Agent** 用 | `sk-` 开头 |

Agent 只认 new-api 的 `sk-` 令牌；拿 Chat2API 的 key 去调 3000 端口会报 `invalid token`。

## 4. 接入 AI Agent

统一填这两项：

```
Base URL : http://localhost:3000/v1
API Key  : sk-xxxxxxxx（new-api 令牌）
Model    : deepseek-v4-flash（或附录 A 中任意一个）
```

### 4.1 各客户端配置位置

| 客户端 | 配置方式 |
|---|---|
| **opencode** | 配置文件里 provider 的 `options.baseURL` 填上述地址，`apiKey` 填令牌 |
| **WorkBuddy / Cursor / Cline / Roo Code** | 设置中选「OpenAI Compatible / 自定义 OpenAI」，填 Base URL + Key |
| **Dify** | 模型供应商 → `OpenAI-API-compatible` → Base URL 填 `http://localhost:3000/v1` |
| **OpenAI SDK** | `new OpenAI({ baseURL: 'http://localhost:3000/v1', apiKey: 'sk-...' })` |
| **ChatBox / NextChat 等** | API 地址填 `http://localhost:3000/v1`，密钥填令牌 |

### 4.2 先用 curl 验证链路

在 PowerShell 中（`curl` 是 `curl.exe` 别名，参数用双引号包裹）：

```powershell
curl.exe http://localhost:3000/v1/chat/completions `
  -H "Content-Type: application/json" `
  -H "Authorization: Bearer sk-你的令牌" `
  -d "{\"model\":\"deepseek-v4-flash\",\"messages\":[{\"role\":\"user\",\"content\":\"你好\"}]}"
```

- 返回 `choices[0].message.content` → 全链路正常，可去配客户端；
- 返回 401 → 令牌错（见 5.1 排障）；
- 返回 404 → 渠道 Base URL 写错；
- 返回 502 / 上游错误 → Chat2API 账号掉登录态。

## 5. 排障

### 5.1 常见错误对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `new-api.exe 不存在` | launcher 与 new-api.exe 不在同一目录 | 确认解压完整，用新版 `launcher.exe`（旧版有 `C:\snapshot` 路径 bug） |
| `localhost:3000 拒绝连接` | 网关未起来 | 看终端日志；确认 `data\` 可写；确认 3000 端口未被占用 |
| `401 invalid token` | 用了 Chat2API 的 key 当令牌 | 换成 new-api `令牌` 页生成的 `sk-` |
| 渠道测试 `404` | Base URL 多了 `/v1`（OpenAI 类型）或少了全路径（自定义渠道） | OpenAI 类型填到 `:8080` 为止 |
| `无可用渠道` | 渠道「模型」字段没填对应模型名，或分组不匹配 | 补全模型列表 / 把令牌与渠道分组设为一致 |
| `502` / 上游报错 | Chat2API 账号登录态失效、或平台改版 | 回 Chat2API 重新登录该平台账号 |
| 模型列表为空 | Chat2API 未添加任何账号，或未 `Start Proxy` | 先加账号再启动代理 |
| 想改端口 | 8080 被占用 | 改 `config.json` 的 `chat2api.port` + Chat2API 内端口 + 渠道 Base URL 三处 |
| `config.json 找不到` | 启动器不在解压目录运行 | 在 exe 同目录执行，或恢复 `config.json` |

### 5.2 日志位置

| 日志 | 位置 |
|---|---|
| new-api 运行日志 | `data\logs\`（`--log-dir` 默认 `./logs`） |
| new-api 数据库 | `data\`（SQLite） |
| launcher 输出 | 启动它的终端窗口 |
| Chat2API 日志 | 应用内「日志」页 |

## 6. 日常运维

| 操作 | 命令 / 方式 |
|---|---|
| 启动 | `.\launcher.exe start` |
| 查看端口状态 | `.\launcher.exe status` |
| 再开一次控制台 | `.\launcher.exe open` |
| 重启 | `.\launcher.exe restart` |
| 停止 | 在启动窗口按 `Ctrl+C`（`launcher.exe stop` 在新进程中无法拿到子进程句柄，实际不生效） |
| 开机自启 | 把 `launcher.exe start` 的快捷方式放入 `shell:startup` 目录 |
| 注册为 Windows 服务 | `.\launcher.exe install-service` —— **仅源码态可用**，需先 `npm install node-windows`；打包版未内置该依赖 |

## 附录 B：config.json 字段

| 字段 | 默认值 | 说明 |
|---|---|---|
| `newApi.exePath` | `./new-api.exe` | 相对 `launcher.exe` 所在目录 |
| `newApi.port` | `3000` | 网关端口（同时注入 `PORT` 环境变量） |
| `newApi.dataDir` | `./data` | 工作目录，启动时自动创建 |
| `newApi.env` | `TZ`、`SESSION_SECRET` | `SESSION_SECRET` 建议自行改为随机串 |
| `chat2api.exePath` | `./chat2api/Chat2API.exe` | 转换层路径 |
| `chat2api.port` | `8080` | 需与 Chat2API 内设置一致 |
| `chat2api.enabled` | `true` | 设为 `false` 则不随启动器拉起 |
| `nodeServices[]` | 2 项，默认 `enabled:false` | 可选 Node 版 free-api |
| `autoOpenWebUI` | `true` | 启动后自动开浏览器 |

修改 `config.json` 后需重启启动器生效。

## 附录 C：风险与合规

1. **违反平台 ToS**：Chat2API 通过驱动各平台**网页版**工作，并非官方 API。账号可能被限流、封禁。
2. **稳定性**：平台前端改版会导致转换层失效，需等待上游 Chat2API 适配更新。
3. **禁止商用**：仅供个人学习自用，不得对外提供付费服务。
4. **勿暴露公网**：3000 / 8080 默认只监听本机，请勿做公网端口映射；如需局域网访问，务必先改强密码、开启 Chat2API 鉴权。
5. **供应链风险**：原 `LLM-Red-Team` 系列仓库已被封存且历史版本含恶意代码，本项目未使用；升级转换层时请始终审查上游源码。
